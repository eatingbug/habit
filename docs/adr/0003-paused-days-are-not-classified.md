# ADR-0003 — 일시정지 구간의 **빈 날**은 분류하지 않는다

- **상태:** 채택됨
- **날짜:** 2026-09-01
- **관계:** ADR-0001이 만든 부작용을 막는다
- **영향 범위:** `models/Habit`, `domain/classify.ts`, `domain/streak.ts`,
  `domain/score.ts`, `domain/diagnose.ts`, `domain/lifecycle.ts`, 히트맵·회고 UI,
  `docs/SPEC.md` §3.2·§4.1·§4.3·§4.4·§4.7·§6.3·§7.3

## 문제

ADR-0001은 `createdAt` 이후 기록 없는 지난 날을 전부 `missed`(미스)로 만들었다.
어디에도 lifecycle 예외가 없다. 그래서 3주 일시정지한 습관은 **21일 미스**를 쌓고,
성공률이 무너지고, 연속이 끊기고, `atRiskToday` 배너가 뜨고, 히트맵이 실패 테두리로
도배된다.

이는 CONCEPT §8.2 / 원칙 10과 정면으로 어긋난다 — *"Pause는 삭제가 아닌 진짜 출구,
'나중에 하기'이지 '퀘스트 포기'가 아니다."* 지금 스펙대로 구현하면 일시정지가
**시스템에서 가장 가혹한 선택**이 되고, 사용자는 대신 삭제를 누른다. Focus Mode(§8)가
V2로 연기되어도 회고의 `pause` 액션이 남아 있으므로 V1에서 실재하는 문제다.

## 결정

`Habit`에 **일시정지 이력**을 저장하고, 그 구간의 **빈 날은 어떤 상태도 갖지 않는다** —
`createdAt` 이전 날짜와 똑같이 분류 대상 밖이다.

```typescript
interface PauseInterval {
  from: string;   // 'YYYY-MM-DD' — 첫 일시정지 날
  to?:  string;   // 'YYYY-MM-DD' — 다시 활성이 되는 첫 날. 없으면 아직 정지 중
}

interface Habit {
  // …
  pauses?: PauseInterval[];   // 겹치지 않고 from 오름차순. 추가만 함
}
```

구간은 **반열림 `[from, to)`** 다 — 재개일은 다시 활성이다. `lifecycle: 'paused'` ⟺
마지막 구간에 `to`가 없다(둘은 일치해야 하는 불변식이며, 열린 구간이 권위를 갖는다).

**`archived`도 같은 장치를 쓴다.** 회고의 `archive` 액션은 도착지가 없던 상태였다
(SPEC §3.5에 액션은 있는데 `lifecycle`에 값이 없었다). 이제 `'archived'`를 lifecycle에
더하고, 열린 구간을 똑같이 추가한다 — 보관된 습관도 날을 분류하지 않고 미스를 쌓지
않는다. 차이는 읽히는 방식뿐이다: 보관은 대시보드에서 숨기고 "끝났다"로, 일시정지는
"나중에"로 읽힌다. 둘 다 기록을 남기고 되돌릴 수 있다.

## 핵심 세부 — 일시정지는 `missed` **기본값만** 억제한다, 기록은 아니다

일시정지 구간에 **활동 행이나 건너뜀 행이 있으면 그 날은 평소대로 분류된다.**
억제되는 것은 "빈 날 → `missed`"라는 **기본값 하나**뿐이다.

왜 이 선까지 잘라야 하는가:

- 하루의 상태는 저장되지 않고 매번 계산된다. 구간 전체를 무조건 무시하면, 이미 기록해
  둔 날의 XP·연속이 **일시정지를 누른 순간 소급해서 사라진다.** 번 것을 빼앗는 것은
  이 제품이 어디서도 하지 않는 일이다(원칙 4).
- 반대로 빈 날만 억제하면 규칙이 한 줄이고, "백필은 순수한 회복"(ADR-0001)이 그대로
  성립한다. 일시정지 구간에도 백필은 허용된다 — 실제로 한 날을 채우는 것은 언제나 회복.

## 파급

1. **범위는 별도 술어가 갖는다.** `classifyDay`는 전체함수로 남는다(항상 `DayState`를
   반환). 대신 `isDateInScope(habit, date)`를 두고, 날짜 구간을 순회하는 쪽이 이걸 먼저
   물어 범위 밖 날을 건너뛴다. `DayState | undefined`로 만들면 "범위 밖은 투명하다"는
   한 줄짜리 규칙이 소비자 8곳에 복사되고, `'out_of_scope'`를 유니온에 넣으면 렌더할 일
   없는 값이 모든 UI switch로 새어 나가며 "그 날 무슨 일이 있었나"와 "그 날을 세는가"라는
   다른 두 질문이 한 타입에 섞인다. 술어 하나, 규칙 하나, 테스트 하나.
2. **연속(`computeStreak`) / `engagementStreak`** — 분류되지 않은 날은 `pending`처럼
   **투명**하다. 끊지도 잇지도 않는다. 그래서 재개하면 일시정지 이전의 연속이 이어진다.
3. **비율** — `successRate`·`floorCompletionRate`·강등 판정 모두 분모·분자에서 제외.
4. **`atRiskToday` / never-miss-twice** — 일시정지 구간의 빈 날은 "어제가 미스"가 아니다.
   정지 중인 습관에는 저장 배너를 띄우지 않는다.
5. **백필 프롬프트(ADR-0002)** — 나열 대상은 `missed` 날짜뿐이므로 자동으로 제외된다.
6. **히트맵** — 분류되지 않은 날은 `createdAt` 이전 칸과 동일하게 렌더한다(빈 칸).
   `pending`(중립 회색)과도 `missed`(테두리)와도 구분되어야 한다.
7. **마일스톤(`milestoneBonusXP`)** — 분류되지 않은 날은 런을 리셋하지 않는다.

## 기각한 선택지

**`pausedAt` 단일 필드.** 재개할 때 필드를 지우면 지난 일시정지 구간이 다시 `missed`로
계산된다 — 문제가 그대로 돌아온다. 이력이 필요한 이유는 하루의 상태를 **저장하지 않고
계산**하기 때문이다. 계산에 필요한 입력은 남아 있어야 한다.

**재개일을 새 기준점으로 리셋(`createdAt` 이동).** 공짜에 가깝지만 일시정지 이전의
기록·연속·성장 추이가 통째로 사라진다. "성공을 퇴출하지 않는다"(원칙 11)의 취지와
어긋나고, 예외 하나를 위해 `createdAt`의 의미를 오염시킨다.

**V1에서 pause를 빼기.** 모순은 사라지지만 원칙 10이 약속한 출구가 없어져
all-or-nothing 이탈(§8.2가 피하려던 바로 그것)로 되돌아간다.

## 지켜야 할 성질

- 어떤 날을 `missed → 분류 안 됨`으로 바꾸는 것(= 일시정지)은 연속·성공률·미스 카운트·
  강등 판정 중 **어느 것도 나빠지게 하지 않는다.**
- 일시정지는 **이미 기록된 날의 XP·연속을 절대 줄이지 않는다.**
- `lifecycle === 'paused'` ⟺ `pauses`의 마지막 구간에 `to`가 없다.
