# ADR-0002 — `missed` 다발은 진단하지 말고 먼저 묻는다

- **상태:** 채택됨
- **날짜:** 2026-09-01
- **관계:** ADR-0001이 남긴 미결 문제를 닫는다
- **영향 범위:** `domain/diagnose.ts`, `domain/backfill.ts`(신규 질의), 회고 화면(§6.4),
  `config/tuning.ts`, `docs/SPEC.md` §2.3·§4.4·§6.4·§7, `docs/CONCEPT.md` §6·§12

## 문제

ADR-0001이 기록 없는 지난 날을 `missed`(실패)로 만들면서 미결 하나를 남겼다:
`missed`는 미스로 세지만 **어떤 성분에도 귀속되지 않는다.** 어떤 습관의 미스가
대부분 `missed`이면 지금의 네 규칙 중 무엇도 그것을 설명하지 못한다.

## 왜 어렵나 — `missed`는 정반대인 두 세계를 뭉뚱그린다

- **A. 기록 누락** — 습관은 하고 있는데 기록만 안 한다. 고장 난 건 **기록 루프**다.
- **B. 이탈** — 습관 자체를 놓았다. 고장 난 건 **설계**이거나 **부하**다.

처방이 정반대인데, `missed` 데이터만으로는 어느 쪽인지 **알 수 없다.** 그러므로
`missed`에 성분을 붙이는 순간 그것은 진단이 아니라 추측이다.

## 기각한 선택지

**`missed` 연속을 `cue` 성분으로 올린다.** 층위가 다르다. cue·floor·identity·load는
전부 **Design 단계**의 고장을 가리키고, 기록 공백은 **Record 단계**의 고장이다
(CONCEPT §2의 루프). 처방도 다르다 — *"양치 후에 명상하기"*(습관의 신호)와
*"자기 전에 오늘 기록 확인하기"*(기록의 신호)는 다른 말이다. cue로 뭉치면 신호가
멀쩡한 사용자에게 신호가 문제라고 말하게 된다.

**다섯 번째 성분(`record`)을 지금 추가한다.** 이르다. 이건 규칙이 없는 문제가 아니라
**데이터가 없는 문제**다. 추측의 품질을 올리는 규칙을 얹기 전에, 모르는 것을 물으면 된다.

## 결정

`missed` 연속이 임계치를 넘으면 진단 카드를 만들지 않는다. 대신 **회고 진입 시
미러 바로 위에 일괄 백필 프롬프트**를 띄우고, **그 응답을 진단 데이터로 쓴다.**

> **"이 5일, 하셨나요?"** — 날짜별 한 탭 채우기 / "안 했어요" 한 탭

| 사용자 응답 | 밝혀지는 것 | 그 다음 |
|---|---|---|
| 대부분 채워 넣음 | **A** — 습관은 살아 있고 기록이 고장 | 기록 시점 정하기를 제안 |
| "안 했어요"로 표시 | **B** — 진짜 미실행. 이제 **사유가 붙는다** | 기존 네 규칙이 정상 작동 |
| 프롬프트를 계속 무시 | **B의 최악** — 습관에서 이탈 | 포트폴리오 부하(§8) 영역 |

**새 성분은 만들지 않는다.** 백필로 데이터가 채워지면 기존 네 규칙이 알아서 제대로
진단한다. "빠진 진단"으로 보였던 것은 사실 "빠진 데이터"였다.

이는 회고가 이미 취한 형태와 같다 — **시스템이 제안하고 사용자는 확인만 한다**
(CONCEPT §6.2). 쓰는 게 아니라 고르는 것.

## 규칙

- **트리거:** `missed` 연속이 `TUNING.diagnosis.missedRunForBackfillPrompt` 이상이거나,
  최근 14일의 `missed` 비율이 `TUNING.diagnosis.missedRateForBackfillPrompt` 초과.
- **위치:** 회고 화면(§6.4)의 미러 **위**. 대시보드에는 띄우지 않는다.
- **푸시하지 않는다.** 푸시하면 상태등 안티패턴(§7.4 알림 무감각)에 정확히 걸린다.
  사용자가 회고에 들어왔을 때만 보인다.
- **성분 귀속은 하지 않는다.** `missed`는 미스로 세되 성분을 만들지 않는다 —
  ADR-0001의 현 상태를 유지한다.
- **대칭성이 중요하다.** "채우기"와 **"안 했어요"를 동등하게 눈에 띄게** 둔다.
  한쪽만 쉬우면 그쪽으로 쏠려 데이터가 편향된다.

## 감수하는 것

일괄 백필이 쉬워지면 **사후에 기록을 지어내기**도 쉬워진다. 감수한다 — 남에게 보이는
시스템이 아니라 본인의 시스템이고, 문서는 이미 백필을 필수로 두고 있다(CONCEPT §5).
대칭적인 선택지 배치가 이 리스크에 대한 유일한 완화책이다.

## 나중에 다시 볼 것

`record` 성분을 정식으로 추가할지는 **이 프롬프트를 실제로 돌려 A가 얼마나 흔한지
본 뒤에** 정한다. A가 드물면 만들 이유가 없다. 관찰할 지표: 프롬프트 노출 대비
(채움 / "안 했어요" / 무시) 비율.
