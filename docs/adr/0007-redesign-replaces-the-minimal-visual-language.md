# ADR-0007: 화면은 쉽고 밝은 리디자인으로 전면 교체한다

- 상태: 채택됨
- 날짜: 2026-10-10
- 관계: `docs/SPEC.md` §6.0의 Linear/Notion 미니멀 비주얼 언어를 대체한다.
- 영향 범위: `docs/SPEC.md` §1.2·§6, `docs/CONCEPT.md` §4, `design/`, `mvp/habiquest-linear.html`, `src/theme/`

## 문제

- 증상: 기능이 눈에 안 들어온다.
- 증상: 화면이 복잡하다.
- 증상: 색이 칙칙하다.
- 원인: SPEC §6.0은 절제를 원칙으로 둔다.
- 원인: 그 원칙은 accent 하나를 아껴 쓰고, 게임 요소를 조용히 그리게 한다.
- 원인: 그 원칙은 설명을 화면에 글로 늘어놓는 것을 막지 않는다.

## 결정

- 화면은 [쉽고 밝은 화면을 위한 리디자인](https://github.com/eatingbug/habit/issues/89)의 결정으로 전면 교체한다.
- 기준은 초등학생도 한눈에 알아볼 명료함이다.
- 사용자층은 성인 그대로다.
- 화면에는 핵심 정보만 둔다.
- 설명은 `?` 툴팁으로 옮긴다.
- 색은 밝고 여럿이다. 색마다 `fill`, `ink`, `tint`를 둔다.
- 상태는 색과 함께 아이콘과 글자로도 표시한다.
- 게임 요소(별, 연속, 상태등)는 또렷하게 그린다.
- 시각 기준은 `design/`의 리디자인 아트보드와 `design/_tokens.redesign.css`다.
- `mvp/habiquest-linear.html`은 더 이상 기준이 아니다.

## 고른 대안

- 오늘 화면을 톤 시안 셋으로 그려 비교했다 ([톤 시안 비교](https://github.com/eatingbug/habit/issues/90)).
  - A 체크리스트를 채택했다.
  - B 게임과 C 포커스는 `prototype/today-tone` 브랜치에 남아 있다.
- 지금 §6.0을 조금씩 고치는 안은 버렸다. 미니멀 원칙과 새 원칙이 같은 문단에서 부딪힌다.
- 화면을 하나씩 바꿔 배포하는 안은 버렸다. 옛 화면과 새 화면이 섞이면 같은 개념이 두 모양으로 보인다.

## 결과

- SPEC §6은 아트보드 기준으로 다시 쓴다.
- 동작 규칙은 문장을 바꾸지 않고 새 구조로 옮긴다.
- 도메인 규칙은 바뀌지 않는다.
- 옛 시안 `mvp/habiquest-linear.html`과 `design/`의 옛 아트보드는 SPEC 재작성 때 지운다.
- 앱은 옛 화면과 새 화면을 섞은 상태로 배포하지 않는다.
- 다시 쓰기 전까지 §6.0과 이 ADR이 어긋나면 이 ADR이 이긴다.
